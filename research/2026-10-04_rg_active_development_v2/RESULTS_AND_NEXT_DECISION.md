# RG-active-development-v2.0：实际结果与下一步判断

本轮已完成共享前端重设计、D0 多轮研发、一次有限 LoRA、原 D1 的 64 题八条管线及 16/32 窗口核验预算比较。不是 v1 报告复核，也没有将旧输出改名作为新结果。执行实现起点为 `c0ee648`；比较期间只完善派生统计与说明，没有依据 D1 调整提示、adapter、模型、阈值或搜索机制。

## 1. 现在能做什么，不能证明什么

现在能从自然问题和原文产生可定位的关系见证，并完成全部自然问题回答。但完整关系解析与条件核验仍不可靠，尚未建立可靠的多跳完整证据前端。

本轮最明确的机制结果是：**每道题的最终 reader 提示，在八条管线和两个预算点之间均完全相同。** 搜索并非没有运行；GB/KMeans 反馈细化确实发生，但没有改变最后送给 reader 的内容或顺序。全部配对的答案增益、损害数都是 0，所有题为同分。不能把这种相同输入下的观测相同分数写成总体统计等效，也不能据此宣布粒球/超图普遍无效。

D0 全部是已暴露开发材料，审阅由助手依据问题/原文完成，不是盲审专家金标准。

- 历史 v1 的格式合规为 2/32、整体解析可用为 0/32；v2 为 **32/32 和 10/32**。这是整套研发前后的变化，不是单独某项组件的因果消融。
- 同一 NF4 精度下，adapter off/on 的分组开发验证精确目标匹配为 **2/25 → 11/25**；精确匹配不等同于语义准确率。FP16 off/on 都是 10/25，因此没有把 NF4 的适配收益外推到 FP16。
- B（参考关系诊断）在 8/32 题产出接受见证；C（自身解析串联）在 **6/32** 题产出接受见证，含 2 道 Hotpot、4 道 MuSiQue。两诊断窗口中 B/C 完整束均为 0/32；一个窗口按开放支持标注选择，另一个按固定无 Gold 词法规则选择，条件在 CSV 中分列。
- 58 个已生成候选命题的原文审阅：选定核验器为 TP=8、FP=0、FN=6、TN=44。它仍漏掉 6/14 个支持命题；零观察误接受不是自然运行的无误保证，也不是整体抽取召回率。
- 无效尝试保留：二次解析修订损伤原已正确的父亲方向；较长 NLI 示例过度拒绝；理由加 verdict 的版本仍接受错误命题。没有用全部拒绝来宣布成功。

参考计划仅进入 B 和明确适配数据，没有进入 C 或 D1。详见 `FRONTEND_RESULTS.csv`、`PARSE_REVIEW.csv`、`VERIFIER_SOURCE_REVIEW.csv` 和 `DEV_LOG.md`。

## 4. 反馈、分组与证据交付

D1 有 42/64 个计划通过程序合同；这不是语义正确率。预测关系数为 0/1/2/3/4 的题数分别是 22/7/33/1/1。所有关系方法只在相同的 3 道 Hotpot 题形成程序完整束，另外 **61/64 题回退**；MuSiQue 没有完整束。完整束都只有一个预测关系，未观察到完整的多关系束。

| 方法 | 接受见证的题数，16/32 | 分裂总次数，16/32 | 最终提示相对 Dense 改变题数 |
|---|---:|---:|---:|
| Dense-window | 不执行关系核验 | 0 / 0 | 0 |
| Flat-binding | 11 / 14 | 0 / 0 | 0 |
| GB-fixed | 11 / 14 | 0 / 0 | 0 |
| GB-uniform | 10 / 14 | 168 / 321 | 0 |
| GB-feedback | 11 / 14 | 34 / 57 | 0 |
| KM-fixed | 12 / 14 | 0 / 0 | 0 |
| KM-uniform | 11 / 14 | 168 / 321 | 0 |
| KM-feedback | 12 / 14 | 31 / 48 | 0 |

这些是模型接受事件和调度记录，不是人工确认的事实精度。重叠窗口会重复见证同一事实。反馈比 uniform 少做了分裂，但未改善本轮最终证据或答案；GB 相对同反馈 KM 没有建立额外答案价值；不分组的 Flat 和 Dense 已达到完全相同的答案结果。不能把分裂减少本身包装成答案收益。

交付损失主要在两处：有效关系和完整束稀疏，使大部分搜索走统一 Dense 回退；少数完整束也没有改变 Dense 已交付的提示。不是靠调整最终 scorer 才出现同分，而是 reader 输入已经逐题相同。

对全部 3 个机器完整束查询的有限原文复核进一步发现：

| Hotpot query ID 后缀 | 原文与计划检查 |
|---|---|
| `5a7183185542994082a3e85d` | 问“哪所大学”，计划却把 `?answer` 设为 Baylor 的类型；原文支持局部属性，不是正确答案变量链 |
| `5a845e935542992ef85e23cf` | Jason White → played for → University of Oklahoma 与问题和原句一致；这是一个正确单关系见证，不是高阶表达证明 |
| `5addd7515542990dbb2f7eb0` | Jennifer Kent 与 The Babadook 的作品关系及年份有依据，但核验窗口只说明导演是澳大利亚人，不能证明影片国别条件；按本轮逐条件标准仍属条件误接受 |

第三项不表示该电影在现实中不是澳大利亚电影，也不直接判定 reader 答案错误；问题在于声明的核验依据不足。这些事后检查未用于修改本次输出或再调参。没有对 D1 全部候选做人工事实标注，不能外推整体精度。

## 5. 质量—成本与复跑

预定主机制等权边界，每题逻辑模型+编码秒数如下。它包含解析、抽取、双核验、条件编码和 reader 的按调用归账成本；分裂耗时另列在 CSV。不是单独部署的端到端墙钟基准，不用共享缓存时间冒充部署优势。

因此本轮额外关系搜索没有显示质量—成本优势。实际主 reader 调用 **64 次**，不是 1024 次独立生成；两个指定查询的 GB/KM-feedback@16 共 **4 条**复跑记录绕过 probe 和 reader 缓存。其状态、访问顺序、提示和答案 token 与主运行一致，不声称复跑了所有配置。

真实 reader 输入为 **666–1024 tokens**，全部与 renderer 记录一致。复跑 reader 首调用出现 249.94 秒延迟，原因未确定；不改设置重试，不作为机制失败，其成本完整计入。

整轮已记录 GPU 进程墙钟 **15153.67 秒（4.21 小时）**、CPU 进程时间 **13959.95 秒（3.88 小时）**，新增目录与依赖约 **223.1 MB**，付费 **0**。共 **5310 次记录推理请求**，另有 30 个训练优化步；训练成本已在同一总额中。峰值 CUDA allocated 为 6,565,146,112 bytes。GPU 墙钟包含进程内 CPU 工作，不是纯 GPU kernel 时间。

上述已记录本轮用量低于 6h/4h/2GB 上限。累计已记录 GPU 为 16497.48 秒、CPU 下界为 15355.41 秒；历史未计时 CPU 与 shell/安装开销仍为 unknown，不补成零。资源统计覆盖实际运行和安装文件的已测范围，不声称逐项计量了操作系统全部开销。详见 `RESOURCE_SUMMARY.json`、`ACTUAL_CALL_COSTS.csv`、`cost.jsonl`。
