# v2.2 development correction

The v2.1 semantic-revision pass did not improve the six-question regression set and reversed the previously correct `has father` relation on index 26. It is retained in local run records but is not the default. v2.2 uses one direct constrained plan with additional invented role examples. Extraction is now one relation per call: the program assigns relation IDs and exact literal offsets; the model locates short mentions and support sentence IDs. This removes the observed arbitrary occurrence indices and wrong slot assignments without repairing unsupported entities. Repeated identical strings use the first exact occurrence within the selected sentence; full original sentence context still reaches the verifier.

v2.2 A: 4/6 regression plans are usable (indices 1/18/24/26); the publisher target and unspecified island still fail. In B, exact spans are now recovered, but the old JSON-payload binary softmax gives high scores to obvious false relations. A v2.3 diagnostic serializes the same propositions in readable role order and generates an actual yes/no verdict: it rejects the false headquarters/self relation, Image Comics publication links, album/label confusion and county/building confusion. It also rejects a supported album/artist relation (false rejection). This is a development observation, not a calibrated probability. v2.3 uses this shared serialization for both diagnostic and runtime verification; non-yes responses are rejected. Constant-to-mention binding is now checked before semantic verification, so a different literal entity cannot be accepted as the requested anchor.

Full D0 development exposed remaining semantic failures. v2.4 negative/positive NLI examples mostly suppressed all verdicts, including correct relations; it is not evidence of high useful precision. v2.6 short evidence-description plus verdict often described the relation correctly but still accepted the wrong claim; this variant is not selected.
