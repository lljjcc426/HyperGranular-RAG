## Decision

Stage4B-U1 governance is reduced to controls that can affect data selection, Gold isolation, algorithm behavior, rankings, metrics, or statistical conclusions. Process-wrapper details that cannot affect those scientific objects are no longer promoted into separate scientific Hard Failure amendment chains.

This amendment:

1. closes Hard Failure 23 after independent acceptance;
2. marks the 1.1.7–1.1.9 PowerShell launcher/remote/observer/PRE chain as historical failed implementation;
3. declines the proposed nested durable-capture Amendment 1.1.10;
4. freezes the scientific method and endpoints unchanged;
5. establishes a three-level review system and a simplified future execution architecture.

No historical tracked file, failure evidence, approval, or negative result is deleted or rewritten.

## Three-Level Review System

### Level A: Scientific-Critical Change

Formal preregistration, user approval, Git freeze, and independent verification remain mandatory for changes to samples, Gold isolation, granular-ball or hyperedge construction, candidate ranking, encoder, thresholds, protected prefix, insertion budget, U1 features/formula/weights/cutoff, endpoints, statistical tests, advancement gates, or any code that can change decisions, rankings, or metrics.

### Level B: Integrity Change

Cache binding, query-ID digest, nullable schema, effective-K, NaN/Inf, membership, duplicate IDs, atomic output promotion, Gold-field scanning, and ranking-subset validation require focused tests, one code review, and one complete suite when relevant. Repeated package reviews and multi-layer process proofs are not required unless the change can alter a scientific result.

### Level C: Runtime Infrastructure

Quoting, command-line byte representation, terminal NUL, launcher stderr formatting, GitHub TLS/remote queries, local tool permissions, shell aliases, stdout framing, push visibility delay, wrapper collection counts, and observer/adapter/parent/loader process topology are engineering incidents. They are recorded in ordinary run logs and become scientific Hard Failures only if they cause wrong data/configuration, Gold leakage, untrusted rankings, changed metrics, or partial official-output promotion.

## Bounded Infrastructure Retry

A future execution protocol may preregister eligibility for at most one Level-C retry only when all of the following are established before the retry. The retry remains non-automatic and requires explicit user confirmation at execution time:

- failure occurred before official input was opened;
- no decisions, rankings, policy, or run manifest was generated or promoted;
- Gold was not read;
- code commit, configuration SHA, and input/cache SHA remain unchanged;
- the correction is limited to wrapper, permission, network, or logging infrastructure;
- the first failure and retry reason are recorded in the same audit.

This amendment does not authorize a retry of the terminated 1.1.9 chain. Data-hash mismatch, Gold leakage, invalid rankings, metric access, algorithm changes, partial official-output promotion, or post-endpoint parameter changes remain non-retriable without a new approved scientific amendment.

## Simplified Future Pre-Gold Architecture

The replacement execution design is limited to:

1. one frozen JSON configuration containing code/input/cache identities and all scientific settings;
2. one direct Python preflight/controller command;
3. one preflight covering local code/config/input/cache identity, Gold unavailability, output absence, runtime versions, and relevant worktree changes;
4. one controller run that reads only unlabeled inputs and atomically promotes decisions, rankings, policy, and run manifest;
5. one independent verifier for effective-K, unique IDs, membership, protected Dense prefix, planned inserts, trigger semantics, and ranking-subset validity;
6. a frozen and committed ranking before any separate Gold evaluator is connected.

Runtime command-line byte equality, instantaneous GitHub-main lookup, terminal-NUL modeling, empty-stderr requirements, and multi-layer PowerShell process counts are removed from the future scientific hard-gate set.

The simplified config, runner, preflight, verifier bindings, and exact commands are not implemented or authorized by this document. They require a small, separate protocol-and-code change before any official input or Gold access.
