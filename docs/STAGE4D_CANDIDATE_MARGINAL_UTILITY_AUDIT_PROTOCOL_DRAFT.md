## 3. Research Question

Primary research question:

> For a candidate knowledge unit generated by the frozen q25 expansion, do deployment-time Gold-free features predict whether inserting that candidate into the protected effective Top-K provides marginal evidence gain, redundant evidence, or displacement harm?

Secondary questions:

1. Can the frozen candidate generation be instrumented into a deterministic, auditable candidate trace without changing q25 semantics?
2. Are candidate-level gain and harm events supported by enough independent query clusters for grouped out-of-fold analysis?
3. Does a fixed low-capacity model separate `MARGINAL_GAIN` from `DISPLACEMENT_HARM` more reliably than the original query-level U1 score and simple candidate score/rank baselines?
4. Are observed signals reproducible across folds and query-cluster bootstrap samples without Gold-derived, question-type, or identity features?

The protocol tests feasibility and learnability. It does not test candidate-controller efficacy.

### 6.2 Frozen candidate universe

For each query `q`, Channel A must use the frozen Stage4B retrieval parameters and pure Gold-free retrieval semantics. It may instrument those semantics but may not change them.

Definitions:

```text
C_q = all official candidate units belonging to q
K_q = min(20, |C_q|)
P_q = min(10, K_q)
B_q = min(4, K_q - P_q)
```

1. Recompute the full Dense order on `C_q` by descending query-unit cosine similarity, then ascending native non-empty `unit_id`.
2. Rebuild granular balls, seed balls, selected facet edges, expanded units, scores, and q25-floor filtering using the exact frozen parameters.
3. Deduplicate expanded units by the frozen highest-rerank-score rule and order them by `(-rerank_score, unit_id)`.
4. Remove units already present in the protected Dense prefix of length `P_q`.
5. The remaining ordered list is the candidate universe `E_q`. It includes eligible candidates beyond the original insert budget so that feasibility is not restricted to candidates selected by the fixed budget.
6. If `B_q = 0` or `E_q` is empty, the query remains in the query trace with zero candidates and contributes no candidate row.
7. Candidate rank is one-based and contiguous in `E_q`.
8. `candidate_proposed_insert_position = P_q + rank` only when `rank <= B_q`; otherwise it is null.
9. The original all-query q25 inserted set is the first `min(B_q, |E_q|)` members of `E_q`.
10. The reconstructed Dense Top-K, q25 Top-K, and inserted IDs must match the frozen ranking artifact exactly for all 4,500 queries.

Duplicate `(query_id, candidate_unit_id)` rows, a protected-prefix candidate, non-contiguous candidate ranks, or any ranking mismatch are terminal integrity failures.

## 8. Candidate Counterfactual Semantics

### 8.1 Metrics

For a ranking `R` and non-empty Gold unit set `G_q`:

```text
ER@20(R) = |set(R[:20]) ∩ G_q| / |G_q|
CR@20(R) = 1 if G_q ⊆ set(R[:20]), else 0
```

For effective `K_q < 20`, `R` contains exactly `K_q` unique units and the same definitions operate on the whole effective ranking.

### 8.2 Single-candidate insertion — primary attribution

For every candidate `c in E_q`:

1. start with the frozen Dense effective Top-K;
2. preserve the first `P_q` units;
3. insert only `c` immediately after the protected prefix;
4. append Dense units in their original order, skipping duplicates;
5. truncate to `K_q`;
6. record the uniquely displaced Dense unit, if any;
7. compute `delta_single_cr = CR(single_c) - CR(Dense)`;
8. compute `delta_single_er = ER(single_c) - ER(Dense)`.

Every candidate is tested at the same first available insertion position. The candidate's original q25 eligible rank is retained as a feature; it does not change the single-insertion position.

### 8.3 Leave-one-candidate-out — fixed set-context attribution

Only candidates in the original q25 inserted set receive LOO values:

1. remove `c` from the full ordered eligible list `E_q`;
2. rerun the frozen protected rerank with the original `B_q`;
3. allow the next eligible candidate to backfill the vacated budget position;
4. rebuild the effective Top-K;
5. compute `delta_loo_cr = CR(q25_full) - CR(q25_without_c_with_backfill)`;
6. compute `delta_loo_er = ER(q25_full) - ER(q25_without_c_with_backfill)`.

Candidates outside the original insert set have null LOO fields. No no-backfill alternative is computed. The with-backfill definition is frozen to measure the candidate relative to the next available choice.

### 8.4 Displacement attribution

For each candidate, Channel B records target-only facts:

- whether the candidate is in the Gold unit set;
- whether the single displaced unit is in the Gold unit set;
- single-insertion and LOO CR/ER values and deltas;
- whether the candidate provides previously unretrieved Gold evidence;
- whether displacement removes previously retrieved Gold evidence.

These fields are diagnostic targets and may never enter Channel A or any feature matrix.

### 8.5 Determinism and edge cases

- Candidate, Dense, and backfill order use frozen ordering and tie-break rules only.
- Effective-K, protected prefix, and insert budget use `K_q`, `P_q`, and `B_q` above.
- A candidate already in the protected prefix is invalid and rejected.
- A candidate already in the unprotected Dense tail may move earlier without displacing a unique unit; this yields `has_displaced_unit=0`.
- Duplicates, empty IDs, missing candidates, non-finite numbers, or a candidate not belonging to the query pool are terminal failures.
- Multi-candidate effects are represented only by the fixed with-backfill LOO calculation. No pair search or higher-order interaction search is authorized.

## 9. Candidate Label Definitions

Each candidate receives exactly one mutually exclusive primary label using this priority:

1. `MARGINAL_GAIN` when `delta_single_cr > 0`, or when `delta_single_cr = 0` and `delta_single_er > 0`.
2. `DISPLACEMENT_HARM` when `delta_single_cr < 0`, or when `delta_single_cr = 0` and `delta_single_er < 0`.
3. `INTERACTION_DEPENDENT` when both single deltas are zero, the candidate is in the original q25 insert set, and either LOO delta is non-zero.
4. `REDUNDANT_GOLD` when all applicable single and LOO deltas are zero and the candidate belongs to the Gold unit set.
5. `NEUTRAL_NOISE` when all applicable deltas are zero and the candidate does not belong to the Gold unit set.

A secondary subtype records `CHAIN_GAIN`, `EVIDENCE_GAIN_ONLY`, `CHAIN_HARM`, `EVIDENCE_HARM_ONLY`, `SET_CONTEXT_GAIN`, `SET_CONTEXT_HARM`, `REDUNDANT`, or `NO_EFFECT` without changing the primary label.

This draft deliberately treats ER-only improvement as marginal gain and ER-only loss as displacement harm. It does not use `candidate_is_gold` as the primary utility definition.

Post-result category merging, splitting, direction flipping, or relabeling is prohibited.

### 13.1 Fixed tasks

```text

Task B: DISPLACEMENT_HARM vs all other primary labels
Task C: MARGINAL_GAIN vs DISPLACEMENT_HARM
```

### 13.2 Fixed folds

Use:

```text
GroupKFold(
  n_splits=5,
  shuffle=true,
  random_state=20260719,
  groups=query_id
)
```

The exact fold assignment must be serialized before model fitting and reused for every task and panel. If the implementation library cannot supply these exact semantics, the implementation must pause before label analysis and request a protocol amendment; it may not substitute another split.

### 13.3 Fixed preprocessing

Within each training fold only:

1. validate finite numeric inputs;
2. median-impute permitted nullable numeric fields;
3. fit mean/standard-deviation scaling;
4. map zero-variance features to zero;
5. apply the training statistics to the held-out fold.

No preprocessing statistic, feature selection, class prevalence estimate, or calibration fit may use a held-out fold.

### 13.4 Fixed model

The only learned probe in this draft is L2-regularized logistic regression:

```text
penalty = L2
C = 1.0
solver = lbfgs
max_iter = 1000
tol = 1e-8
fit_intercept = true
class_weight = none
random_state = 20260719
probability threshold = 0.5
```

No hyperparameter search, class reweighting, threshold optimization, shallow tree, gradient boosting, neural network, automatic feature generation, or model selection is authorized in v1. All four panels are reported; the primary decision uses `COMBINED_DEPLOYABLE_28` only.

### 13.5 Fixed baselines

For every eligible task, report without direction flipping:

- original query-level U1 raw score, repeated only for baseline comparison;
- `dense_score`, higher-is-positive;
- negative candidate eligible rank, higher-is-positive after sign;
- `facet_score`, higher-is-positive;
- a training-fold prevalence probability baseline.

Scalar non-probability baselines receive AUROC/AP only. The prevalence baseline receives Brier and calibration summaries.

## 14. Metrics And Uncertainty

For every eligible task and fixed feature panel, report:

- OOF AUROC;
- OOF average precision;
- OOF Brier score;
- calibration intercept and slope;
- fixed-threshold 0.5 confusion matrix;
- prevalence and candidate/query-cluster counts;
- every fold's AUROC, AP, Brier, confusion matrix, positive candidate rows, negative candidate rows, positive query clusters, and negative query clusters;
- candidate-score/rank and original-U1 baselines;
- paired differences from the original U1 score for Task C.

Calibration intercept/slope use an unpenalized logistic recalibration of the binary outcome on `logit(clip(p, 1e-6, 1-1e-6))`. A degenerate fit is null with an explicit reason; it may not be replaced by another method.

Uncertainty uses 10,000 query-cluster bootstrap resamples with seed `20260719`:

1. sample query IDs with replacement at the observed query count;
2. include all candidate rows belonging to each sampled query, preserving multiplicity;
3. recompute metrics and paired baseline differences;
4. report percentile 95% intervals.

No candidate-row bootstrap, fold-level t-test, p-value fishing, or post-hoc multiplicity correction is permitted. All panels and tasks must be reported, including failures and null results.

Decision priority is `PROCEED`, then `STOP`, then `INCONCLUSIVE`.

### 15.1 `PROCEED_TO_STAGE5A_U2_PROTOCOL_DESIGN`
